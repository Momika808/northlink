# Northlink — лендинг

Одностраничный сайт личного VPN-контура: что это, где входные узлы и как
подключиться на iOS, Android, Windows, macOS и телевизоре.

Страница статическая и без единого внешнего запроса при загрузке — ни
шрифтов, ни аналитики, ни библиотек; в сеть она выходит только по действию
человека (код → чат с ботом). Это не аскетизм: конфиг нужен ровно тогда, когда
туннель уже не работает, и страница обязана открыться на умирающем канале.

## Раскладка

| | |
|---|---|
| `index.html` | вся страница: разметка, стили и скрипт в одном файле |
| `csp.py` | пересчёт хэшей скриптов для CSP в `index.html`; запускать после любой правки скрипта |
| `.nojekyll` | GitHub Pages отдаёт файлы как есть, без сборки Jekyll |
| `Dockerfile`, `nginx*.conf`, `.gitlab-ci.yml` | образ копии страницы для `ru.adminwg.dad`; собирается в зеркале gitlab `vpn/landing`, на GitHub не используются |

## Копия на ru.adminwg.dad

С 23.09.2026 та же страница открывается на `https://ru.adminwg.dad/` — для
сетей, где зарубежные адреса режут и GitHub Pages не открывается. В DNS у
этого имени только ретранслятор в Москве, дальше путь идёт через фронт на
ядро. На копии чат, выдача ключа и жетоны MAS идут на тот же адрес
(`ON_RU` в скрипте); на `auth.adminwg.dad` остаются только экраны входа и
регистрации. Копию собирает конвейер зеркала `vpn/landing`, выкатывает Flux
(`cluster/vie`, `apps/northlink-sayt`): правка доезжает до копии, когда
доехала до зеркала.

## Правки

Меняется один файл, публикуется коммитом в `main` — Pages пересобирает сам.

После правки любого `<script>` в `index.html` — `python3 csp.py`: страница
несёт CSP в `<meta http-equiv>` (Pages заголовков не ставит), встроенные
скрипты разрешены по sha256-хэшам. Без пересчёта браузер скрипты не запустит,
страница молчит, в консоли — «Refused to execute inline script». Стили —
`unsafe-inline`, сеть — только `cdn.`, `matrix.`, `auth.adminwg.dad`,
картинки чата — `blob:`.

С 13.09.2026 страница — один экран: название, две фразы, окно чата с ботом
и четыре честных пункта. Инструкции по приложениям, ссылки на скачивание и
частые вопросы живут в боте (репозиторий `vpn/bot`, `northlink/spravka.py`)
и приходят в чат в момент, когда нужны: выбрал приложение — получил ссылку,
«Скачать» и шаги; кнопка «Вопросы» — ответы. На странице их больше нет.

- **Вход и чат с ботом** — секция `#get`. Без входа чата нет: две кнопки,
  «Войти» и «Зарегистрироваться», ведут на сервер входа `auth.adminwg.dad`
  (MAS). Страница — публичный OIDC-клиент `01M2MYTNBN9SXN2469ZEYBJAXQ`
  с PKCE (S256) без секрета: адреса берёт из
  `/.well-known/openid-configuration` (кэш в `sessionStorage`; ответ и кэш
  принимаются, только если `issuer` наш и все адреса на
  `https://auth.adminwg.dad/`), редирект
  на `/authorize` с `response_mode=fragment`, «Зарегистрироваться» —
  тот же адрес с `prompt=create` (запасная ссылка — `auth.adminwg.dad/register`).
  На возврате сверяет `state` из `sessionStorage`, меняет код на жетоны
  (`POST /oauth2/token`), чистит адрес через `history.replaceState`.
  Жетоны — в `localStorage` под `northlink.oidc` (access на 300 с, refresh
  с ротацией, `expires_at`, `device_id`); `device_id` отдельно под
  `northlink.device`, чтобы устройство в Matrix было одно. Обновление —
  за 60 с до истечения и перед запросом с истёкшим жетоном, под
  `navigator.locks` с перечитыванием хранилища: две вкладки не выбивают
  друг друга. Дальше: `whoami` на `matrix.adminwg.dad` → имя учётки,
  `POST https://cdn.adminwg.dad/api/session` с Bearer → ссылка, срок и
  комната; страница принимает приглашение (`/join/{room_id}`) и говорит
  с ботом сама — `/sync` длинным опросом, `PUT …/send`, картинки с жетоном.
  «Выйти» — `POST /oauth2/revoke` для обоих жетонов, хранилище стёрто,
  ссылка «завершить сессию на auth.adminwg.dad/account/» (браузерную сессию
  сервера входа revoke не трогает). Следующий вход просит только согласие,
  пока жива браузерная сессия `auth.adminwg.dad`; пароль спросит после
  завершения сессии в `/account/` (страница шлёт `prompt=login`, но MAS
  1.24 его не учитывает). Другие вкладки узнают о выходе по событию
  `storage` и сразу показывают вход. На `401` от Matrix в чате — один
  повтор со свежим жетоном (соседняя вкладка могла обновить пару раньше),
  второй `401` подряд — «Сессия закончилась». `403 key_revoked` от
  `/api/session` (ключ сгорел или отозван) показывается текстом сервера.
  Ссылка ключа берётся из ответа сервера при каждом входе,
  `northlink.issued` — только кэш. Старый чат по личной сессии
  (`northlink.matrix`, учётки `@nl-…` без пароля) работает как раньше, пока
  человек не нажмёт «Забыть её здесь».
  Библиотек нет, API клиента Matrix и OIDC вызывается голым `fetch`,
  PKCE — WebCrypto. Кнопки — как в Telegram: inline-клавиатура под
  сообщением бота (поле `dad.adminwg.northlink.choices`: ряды кнопок,
  стили primary/success/danger, url со стрелкой; после нажатия — спиннер,
  бот правит сообщение через `m.replace`) и постоянная над полем ввода
  (событие состояния комнаты `dad.adminwg.northlink.keyboard`,
  сворачивается значком). Нажатие уходит как `body`=подпись и поле
  `dad.adminwg.northlink.press`. При загрузке без входа внешних запросов
  ноль; с входом страница ходит только на три своих имени.
- **Не подключается?** — карточка `#help` в герое, под чатом (с 18.09.2026).
  Три шага для человека на сломанной сети: обновить подписку, выбрать узел
  «Россия → …», нажать «Не работает» в чате. Зачем на сайте, а не только в
  боте: из российских сетей сайт открывается (7 из 7 замеренных), Telegram —
  нет. Тот же текст — в боте («Вопросы» → «Перестало подключаться»,
  `northlink/spravka.py`, ключ `broken`); менять вместе. Имена узлов писать
  ровно как в подписке; адресов и названий операторов на странице нет.
- **Честно** — секция `#trust`, четыре пункта; тексты дублируются в боте
  («Вопросы» → «Что важно знать заранее»).
- **Бот** — ссылки `t.me/northlink_bot` в шапке и в чате.
- **Города** — строка над заголовком и в подвале: только входы (Франкфурт,
  Варшава, Амстердам). Вена — ядро, не вход, на странице её нет; российский
  вход назван в питче словами, без города.
- **Дизайн** — тёмная тема, сияние и вёрстка сохраняются. Почему это
  подходит теме и что подтягивать (контраст, цели касания, отступы,
  сияние на телефоне) — ранбук «Дизайн лендинга Northlink» в cluster/vie:
  `docs/runbooks/northlink-дизайн.md`. Правило: не добавлять шрифты,
  аналитику, картинки с CDN; предел — 100 КБ HTML.
- **Индексация** — `<meta name="robots" content="noindex, nofollow">` в `<head>`.
  Строка стоит намеренно: прямая ссылка работает, поисковики и сканеры
  блок-листов страницу не находят. Убирается одной правкой.

## Чего здесь нет

Адресов узлов, домена панели, ключей и любых других данных контура.
Инфраструктура живёт в отдельном закрытом репозитории; сюда попадает только
то, что и так видит любой человек с подпиской.

## Проверка оплаты

`payment-check.html` открывается из меню и из `diag.html`. По нажатию она
отправляет только `{"kind":"payment"}` в существующий `POST /api/diag`
Northlink (vpn/bot). Сервер делает GET /me ЮKassa, возвращает номер отчёта
`PD-…` и объяснение. Никаких платежей проверка не создаёт. По номеру владелец
находит запись `payment_diagnostic` в журнале бота. Аккаунт не передаётся:
для своей истории платежей человек использует `/paycheck` в личном чате.

Сбой до ответа сервера сохраняется только в поле отчёта на странице.
HTTP 200 API — не доказательство успешного создания счёта или оплаты.
Ошибки чужой страницы ЮKassa/банка этому сайту недоступны.

Сначала выкатывается backend с kind=payment, затем сайт. Старый backend
покажет «проверка пока недоступна», существующий отчёт связи не меняется.
У новой страницы собственный CSP-хэш встроенного скрипта: при правке JS
пересчитать SHA-256 точного содержимого между <script> и </script>.
Локальная проверка сценариев и CSP: `node --test tests/payment-check.test.cjs`.

## Общая диагностика и российские сервисы

`diagnostics.html` объединяет связь/подписку, российские сервисы за границей
и оплату. `ru-check.html` получает targets из /api/diag: тот же актуальный
список явных исключений MIHOMO в панели, что использует бот /bypass. Отдельной
ручной копии доменов в сайте нет. GEOIP/GEOSITE — категории правил, а не полный
перечень всех возможных российских сервисов; страница честно различает это.

По нажатию: страна проверочного адреса через ipwho.is, GET favicon.ico доменов
правил (6 параллельно, 6 секунд на запрос), сохранение строгого отчёта через
kind=network. ND-номер ищется в network_diagnostic. IP и токены серверу не
отправляются. Режим current/ru выбирает человек, он не считывается из VPN.
В Rule IP проверочного домена не доказывает маршрут российских сервисов.
У непрозрачного no-cors ответа нет доступного HTTP-кода: даже 403/404 может
дать сетевой ответ. Вход, операции и геоблокировка этим не подтверждаются.
Сравнение двух запусков показывает изменения сетевых ответов по доменам.

ipwho.is: https://ipwhois.io/documentation (success, country_code, CORS/лимиты).
Нужного набора ipwhois в локальном doku нет; прочитан официальный источник.
Пересчитывать CSP-хэш ru-check.html после изменений встроенного скрипта;
тест проверяет его соответствие точному содержимому.

27.10: при отказе API отчёт сохраняет этап (получение каталога/пробы/запись),
статический адрес API, HTTP-код либо различение тайм-аута/ошибки сети/JSON и
число завершённых проб. Ранее эти причины скрывались одним общим текстом.
Неуспешная проверка больше не помечается как завершённая. Сырой текст ошибок
браузера/ответа API в отчёт не копируется, результаты выполненных проб остаются.
